## MCTS production-claim audit — determinism + side-asymmetry — 2026-05-15

Two coupled unknowns gated how honestly the production claim
(search-wrapped **rollout-leaf** MCTS @ W6 iter-2, aggregate Wilson lower
**0.6479**, manifest `runs/R13-W6-phase-d/iter-2/gate.manifest.json`, git
`bc6db85`) can be stated. Both resolved here read/measure-only — no new
training, no new MCTS-selfplay, no orchestration framework.

**(a) Single-worker CRN determinism — PASS, 0.0 divergence.** R14.B's
AsyncLocalStorage fix (R-WILD #34) only closed the *parallel-worker*
serial-vs-parallel case (`training/r14_determinism_smoke.py`,
workers=1-vs-4). Single-worker *self-consistency* was unaudited. New thin
wrapper `training/r15_single_worker_determinism_replay.py` replays the same

rolloutSteps=200 collapse=64 maxNodes=5000 prior=policy opp=rule

frozen iter-2 checkpoint/ONNX is `STATE_DIM=96` schema v2; current `feat/ai`
HEAD emits 110-dim schema v3.0 (R7.b.2 Phase 2, commit `301759e`), so the

**Cheap-inference envelope reconciliation.** Value-head-leaf's documented
0.39–0.45 envelope is three independent seed ranges: F-iter-2 0.443
(820000+), R14.A 0.404 (800000+), R14.A.footnote 0.394 (900000+). The
adaptive-ratio=1.5 cell sits at the **top** of that band (0.4524) but the
honest envelope-low is the R14.A.footnote 0.394 — **1-of-3 below the 0.40
production bar**. Value-head-leaf is therefore *at* the bar, not safely
above it; rollout-leaf clears the same bar by ~25pp aggregate.

**Recommended production config: rollout-leaf @ W6 iter-2.** Rationale,
tradeoff stated explicitly:

- **Strength dominates by ~20pp aggregate Wilson lower** (0.6479 vs
  best-case value-head 0.4524, vs honest-envelope-low 0.394). Even
  rollout-leaf's *player-side floor* (0.5577) is above value-head's
  *aggregate best case* (0.4524). This is the decisive factor.
- **Latency is the cost paid.** Rollout-leaf is ~2.5× slower
  (value-head-leaf cuts 61% wall-clock; ~0.5s/decision vs rollout's
  multi-second decisions). For an asynchronous / turn-based card game with
  no hard real-time SLA, a few-second decision is acceptable; the strength
  delta is not worth trading for sub-second latency. If a future hard
  latency SLA emerges (e.g. live multiplayer with a move clock),
  value-head-leaf + ratio=1.5 is the documented fallback — but it must be
  shipped with the honest "*at* the 0.40 bar, 1-of-3 seed ranges below"
